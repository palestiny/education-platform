# Architecture Decision Records

Architecture Decision Records document significant architectural decisions.

Each ADR should contain:
- ID and title
- Status
- Date
- Context
- Problem
- Decision
- Alternatives considered
- Trade-offs
- Consequences
- Evidence
- Confidence
- Related decisions
- Supersession information when applicable

## Statuses

PROPOSED, ACCEPTED, REJECTED, SUPERSEDED.

Do not silently edit the meaning of an accepted architectural decision.

If a later decision changes an accepted decision, create a new ADR and mark the previous ADR as superseded.

No ADR is required for every coding detail; use ADRs for decisions whose consequences materially affect architecture or long-term system structure.
