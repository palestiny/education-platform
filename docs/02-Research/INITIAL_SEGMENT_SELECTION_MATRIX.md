# Initial Segment Selection Matrix

**Status:** Research Instrument  
**Gate:** Product Foundation / Competitive Intelligence — NOT PROVEN  
**Implementation:** Not authorized

## Purpose

Select where to run direct workflow validation first without treating the segment as a product decision.

The matrix is a research planning tool. It does not rank markets or declare a winning segment.

## Candidate Contexts

1. Private tutoring: teacher + parent + student
2. Tutoring center: teacher + coordinator + parent + student
3. School: teacher + coordinator + parent + student

## Research Criteria

| Criterion | What to verify |
|---|---|
| Role proximity | Can the same learner's case be reconstructed across relevant roles? |
| Case recurrence | Do intervention cases occur often enough to observe real examples? |
| Cross-role dependency | Does action require more than one role? |
| Evidence fragmentation | Is evidence distributed across systems, messages, notes or memory? |
| Follow-up burden | Is follow-up explicit or dependent on manual reminders? |
| Closure visibility | Can participants tell whether the case was resolved? |
| Outcome evidence | Is there observable evidence after intervention? |
| Existing tooling | What already handles the workflow? |
| Workaround visibility | Can current workarounds be observed directly? |
| Access feasibility | Can real participants and recent cases be reached ethically? |
| Privacy complexity | Can the workflow be studied without collecting unnecessary sensitive data? |
| Failure/recovery | Are missed actions, connectivity, scheduling or communication failures observable? |
| Segment specificity | Can the problem be described without broad market assumptions? |

## Selection Method

Do not assign an overall score.

Instead, record for each segment:

- **Evidence availability:** HIGH / MEDIUM / LOW / UNKNOWN
- **Access feasibility:** HIGH / MEDIUM / LOW / UNKNOWN
- **Cross-role workflow visibility:** HIGH / MEDIUM / LOW / UNKNOWN
- **Known uncertainty:** brief factual note
- **Research risk:** brief factual note
- **Decision:** TEST FIRST / TEST LATER / HOLD — only after evidence review

These labels are operational research states, not product quality rankings.

## Initial Research Focus

The existing research protocol proposes starting with private tutoring / tutoring-center workflows because the same learner may interact with a parent and multiple educators. This remains a research hypothesis, not a validated market choice.

Before collecting cases, confirm:

1. participants can describe a real recent intervention;
2. the case involves at least two relevant roles;
3. current tools/workarounds can be inspected or reconstructed with permission;
4. outcome or closure can be investigated;
5. privacy/consent boundaries are acceptable.

## Stop / Pivot Conditions

Move to another segment if:

- access produces only hypothetical opinions;
- real cases cannot be reconstructed;
- cases are too rare to investigate;
- existing tools consistently close the loop with little friction;
- privacy/consent prevents responsible research;
- evidence indicates the main problem is different from cross-role intervention coordination.

## Decision State

**Current:** No segment has been validated as the product's initial market.

**Next:** collect real cases, then compare evidence across segments.
